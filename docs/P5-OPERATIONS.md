# P5 故障处理与可见性

基于 P4 投递状态账本扩展，保留原单容器与数据目录。新增「故障中心」导航。

## 功能
- 故障中心：按账号/任务汇总明确失败和结果待核查，保留 P4 状态边界。显示最近 25 组错误和投递状态指标。
- 重试概览：按排期、领取、暂停、人工、阻止、用尽、过期汇总；不更改重试算法；自动重试仍默认关闭。
- 监听状态：区分停用、启动中、已注册且客户端已连接、断连、计划重启、离线；不将任务启用误判成健康。
- 记录导出：管理员 GET /api/relay/export，CSV，按 account_id/task_id/status/from_ts/to_ts 过滤，默认 5000 最多 10000 条；只输出元数据，UTF-8 BOM 和 CSV 公式转义；无正文、会话凭据和队列 token。
- 恢复通知：系统设置中默认关闭；一次先前已成功发送的异常告警建立待恢复标记，故障账本中已无失败及待核查记录后才发一次恢复通知；通知失败会下次检查继续尝试。仅代表当前保留的投递记录已清空，不表示外部 115 Bot 已完成转存。
- 管理 API：GET /api/relay/operations 和 /api/relay/export 均要求管理员会话。

## 安全与迁移
无新数据表，复用已有 SQLite 与设置持久化。已存在的旧历史可继续查询。恢复通知默认关闭、不会在部署时自动发送。失败或待核查不得自行重发；维护策略若清理旧失败记录，恢复通知含义仅限当时保留的账本。

## 验收
- 模拟失败/成功投递校验故障和排期聚合。
- 未登录用户无法访问新接口。
- CSV 公式注入转义、分页上限/时间范围检查。
- 模拟监听器尚未注册时不显示正在监听。
- 仍须在 CI 跑 pytest、ruff、TypeScript、Next 构建与浏览器测试。真实 Telegram/通知发送需在用户环境验收，不应使用真实账号做自动测试。
